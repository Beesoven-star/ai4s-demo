# 集成电路技术观察工作流

## 查看自动发布的观察

本地集成电路工作台运行时，默认每天北京时间 08:00 采集新闻和论文，随后当天约每三小时补查新闻。可在「每日发现 → 采集管理」调整每日采集时间或暂停。手动采集也会触发观察整理。

采集完成后，系统按日期准备材料，并使用「设置」里的模型连接在后台整理。日报使用截至日的资料，周报使用最近七天的资料，复用同一批来源核对结果。整理完成后直接更新「今日观察」和「本周简报」，历史版本继续保留。部分来源无法读取会在报告中标注，模型失败或未配置时仍可在「每日发现」读已入库资料。

在「设置 → 自动观察」编辑提示词、查看近期运行，并可选择日期从已入库资料重跑。每次自动发布保存提示词版本。重跑读取选材所需的公开出处，采集任务独立运行。

日报、周报和专题按实际读到的材料写明出处和结论范围。新闻区分规格预览、样片、量产计划和部署。论文摘要中的结果归给作者，比较数字保留实验条件和基线。来源只有简介或题录时，结论限于这些材料提供的信息。技术评分依据随各项分数展示。

集成电路资料库中新收录的论文有作者摘要时，后台使用「设置」里的模型连接整理中文的主要发现、研究问题、方法和适用范围。详情页在原摘要旁显示阅读依据。后来补到作者摘要的论文也会自动整理，摘要内容相同时沿用已有要点。模型整理期间可阅读已收录的摘要。

## 自动跟踪技术专题

采集完成后，专题任务从截至当日最近 21 天的入库新闻和论文中选材，用已配置的模型识别同一技术方向和独立进展。该任务与日报、周报分别运行。在「设置 → 自动观察」用已有资料重跑时，也会更新专题。

系统先比较进展与既有专题的工程问题和范围。子技术和实现路径归入对应专题。同一事件的多篇报道共用一条进展。现有专题覆盖不到、且已有可追溯技术进展的独立方向，直接进入「技术专题与评价 → 新近跟踪的专题」。专题页展示技术问题、进展、资料和后续验证项。

连续 30 天没有新进展时，专题移到「历史专题」。发现实质新进展后恢复跟踪，沿用原链接和既有进展。旧专题的评价与已经发布的观察版本按原记录保存。

## 热点关注度榜

本地「查看排行」中的热点关注度榜读取已入库的新闻，以北京时间当天为截止日，按来源首发日计算近 7 天和近 30 天的媒体覆盖。近 30 天榜单最多展示排名前 50 条。沿用已有事件归类和来源判断，结合收录的标题、简介识别相似报道。同家媒体只计一家，标明为转载、同稿、公告和赞助的材料不计为独立报道。新采集入库后，打开榜单即可读取更新，页面打开时每分钟检查一次。静态展示和往期简报沿用各自保存的数据。

## 技术评价

后台检查跟踪中专题所关联的材料，材料新增或正文补充才触发评价。模型按瓶颈价值、影响范围和带动作用分别写判断，程序核对资料 ID、原样摘句和正文数字。已知信息可以先形成评价卡。三项都有依据、且引用覆盖不同机构的至少两项独立进展，其中至少一条是作者摘要或已核对的原文要点，才生成总分并加入技术重要性榜。出现无法支撑旧判断的新结果时保留此前评价。

「设置 → 技术评价规则」可查看评分尺度和入榜规则，并编辑补充关注点。保存的偏好会在下次有新证据时使用。

## 在命令行独立试跑

在项目根目录运行。选择已启用的来源 ID，数据会进入一份独立的 SQLite 采集库。日期使用北京时间，取截至当日的七天。省略 `--output` 时，每次运行会建立新的草稿目录。

```powershell
.\.venv\Scripts\python.exe scripts/run_ic_observation_drafts.py --sources thelec_ic mynavi_techplus_ic servethehome_ic todaes_ic --as-of 2026-11-21
```

也可以把已经采过的批次重放，不再请求来源。`--as-of` 可以指定以前的日期，用于检验日报的发布日期和选材。

```powershell
.\.venv\Scripts\python.exe scripts/run_ic_observation_drafts.py --replay-db .runtime/goal-recent-news-20261121.sqlite --as-of 2026-11-20
```

阅读 `observations.md` 查看草稿。`drafts.json` 保存本次采集状态、资料标识、归类依据、候选选材和疑似同事件对。远端来源失败时，可从对应的采集状态和报错看出覆盖缺口。

## 独立试跑可以检查什么

| 步骤 | 自动完成 | 调整规则时可检查 |
| --- | --- | --- |
| 采集和资料去重 | 复用 RSS、公开目录和 Crossref 采集。按规范化 URL、DOI 或 arXiv 标识归并相同资料，与正式库比对是否已收录。 | 检查采集失败或来源缺少可核验日期的情况。 |
| 新闻归并 | 用发表日期和标题共同词提示同一事件的候选报道。 | 核对是否是同一事件、同稿转载、厂商披露、记者独立报道或有新增事实的后续跟进。 |
| 归类 | 自动打大类和专题标签，标出仅在简介中命中的专题和待归类条目。 | 确认文章重点和交叉归类，决定专题是否纳入、合并或暂停。 |
| 日报与周报 | 按报道日期生成日报选材，按七天窗口及议题覆盖生成周报选材。保留原站链接，并摘录可识别的作者摘要原句。 | 取舍材料，核实进展阶段、性能数据和比较条件，确定周报主线、中文表述和发布版本。 |

新闻首次发布时间带有时区时，先换算为北京时间，再按日期筛选。来源只提供日期或未声明时区时，沿用来源日期。集成电路新闻初筛包含 DDR5、DDR6、LPDDR、GDDR 等内存技术关键词。

## 通过命令行维护已有版本

已有离线试跑结果可用 `scripts/seed_ic_editor.py` 导入，输入为试跑输出的 `drafts.json`。重复导入会保留同一批次的已保存编辑。

旧版的命令行发布入口仍可用于维护已有稿件。日报编辑稿可沿用 `scripts/publish_ic_daily.py` 的 `date`、`title`、`intro` 和 `entries` 格式，`source_id` 引用经过核验并已入库的资料。榜单与此前技术评价快照沿用 `scripts/build_ic_briefing.py` 的来源核验和评价口径。
