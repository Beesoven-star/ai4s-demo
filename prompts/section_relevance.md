## 每个点的写法（固定形态）

`- <支撑>。**<我方结论>**`——支撑在前、结论在后，**每点只有结尾一句加粗**：

- **支撑**（1-2 句，不加粗）：今日哪条进展（带链接）+ 它暴露了 01 专项的什么缺口，客观陈述；
- **我方结论**（最后一句，**整句加粗**）：01 专项因此需要补什么 / 跟进什么 / 警惕什么，以「我方…」的视角给出可执行判断，落到具体环节（哪个任务、哪项能力、哪条路线）；
- ❌ **不要在开头另写话题概括句**（如「科学智能体硬件控制标准需加速统一」这类口号句）——每点只保留结尾一个加粗结论；
- 缺口类型按实际情况选择，不要套模板：
  - 有空白：对方已覆盖的能力 / 设施 / 数据，工作文档中尚未布局
  - 有差距：同类任务对方做到的指标 / 水平已领先我们
  - 需跟进：其方法、任务设计、评测思路可直接补入当前工作
  - 需警惕：竞争抢占先机，或暴露当前工作未覆盖的风险

## 核心约束（必须遵守）

1. **不硬拉关系**：相关性必须具体、可说明（同一科学对象 / 同一技术路线 / 直接影响任务的数据、模型、设施或政策）。仅仅"都属于 AI"或"都属于某大领域"不算相关，宁可不写。**弱相关的点整条舍弃，不要凑方向**。
2. **严格锚定素材**：每条判断必须基于今日消息的具体内容，禁止用预训练知识脑补工作文档之外的细节。
3. **行文要求**：
   - 简洁：每点 = 1-2 句支撑 + 结尾一句加粗我方结论，`- ` 开头，独立换行；**禁止**"X方向：A、B、C分别涉及……"这种罗列句式
   - 结论句不写"值得关注""有参考价值"这类空话，必须是具体动作（补齐什么、建立什么、跟进什么）
   - 支撑中的进展带行内原文链接，**必须写成 `[短标题](url)` 的 markdown 形式**（数据取自素材 JSON 的 link 字段），禁止括号裸 URL
4. **无相关就直说**：今日消息均未暴露可查缺补漏的缺口时，按下方固定格式输出。
